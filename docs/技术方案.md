# 本机 AI 陪练 · 技术方案 v0.1

> 代号：**dojo**（命令 `dojo`）
> 目标：装在自己的 Linux 上，AI 就在终端里，实时看着你敲命令，按你选的协助等级帮你，随时能停
> 状态：已实现，v0.6，见仓库 bin/dojo。早期设想的 daemon + unix socket 没有采用，实际是全本地、无守护进程的 CLI；容器版八关练习在另一个仓库待整理

---

## 1. 定位与边界

### 1.1 一句话

你是司机，它是副驾。默认只说话不动手，动手要你点头，全程你看得见，随时能停。

### 1.2 跟 agent 的区别（不是能力区别，是契约区别）

| 维度 | agent | dojo |
|---|---|---|
| 主体 | 给目标，自己跑完 | 你操作，它陪 |
| 默认权限 | 默认可执行 | 默认只读，执行要批准 |
| 可见性 | 结果汇报 | 每一步实时流式 |
| 停止 | 中断任务 | 三种粒度都能停，且停得干净 |
| 成功标准 | 任务完成 | 你能复述刚才发生了什么 |
| 生命周期 | 可后台长跑 | 绑定当前终端会话，CLI 退出即终止 |

一句话：**dojo 不允许「无人值守」这个状态存在**。

## 2. 用户场景

1. 敲了条命令报错，直接问「这啥意思」，它结合刚才的 stderr 解释
2. 想做一件事但不知道从哪下手，让它给方向，它先说思路不给命令
3. 知道要干什么，让它把命令写出来，自己敲
4. 卡住了，让它代跑一步，看着输出，确认没问题再下一步
5. 它跑偏了，按 Ctrl+C 停住，问它现在机器是什么状态

## 3. 术语（先把「停」拆清楚）

| 词 | 含义 | 触发 |
|---|---|---|
| **停手 halt** | 不再执行新步骤，当前命令继续跑完 | 确认点按 n / 一次性计划里发 halt |
| **刹车 brake** | 按下停之后、还没决定怎么停的中间态，命令仍在跑 | Ctrl+C 一次 / `dojo stop` |
| **中断 interrupt** | 给当前命令发信号，让它停下 | 刹车后选了「中断」 |
| **终止 abort** | 放弃剩余步骤 | 确认点按 q / 刹车后选 1-3 |
| **回滚 undo** | 撤销已发生的修改，只覆盖可逆操作 | 停下后 `dojo undo` |

**默认语义：停 = 先回滚。能回滚就回滚，回不了就把这一步跑完再停，绝不把你留在半截状态。**
理由：半截状态最难收拾。中断不是目的，把机器还原到「能接着干活」才是目的。

## 4. 架构

```
┌──────────────┐   JSONL(命令/退出码/cwd/stderr)   ┌────────────────┐
│ shell hook   │ ───────────────────────────────▶ │                │
│ bash / zsh   │                                   │  dojo daemon  │
└──────────────┘                                   │  (systemd user)│
                                                   │                │
┌──────────────┐   unix socket 双向流               │  · 会话状态     │
│ dojo CLI    │ ◀───────────────────────────────▶ │  · 策略引擎     │
│ (前台执行器)  │                                   │  · 模型客户端   │
└──────┬───────┘                                   │  · 日志/快照    │
       │ PTY 子进程                                 └────────────────┘
       ▼
   被执行的命令（stdout/stderr 实时回传）
```

### 4.1 组件职责

- **shell hook**：每次命令结束，把 `command / exit_code / cwd / stderr 尾部 20 行 / 耗时` 写进 socket。非阻塞，50ms 超时，失败静默，绝不打断 shell。
- **daemon**：持有会话上下文、组装 prompt、调模型、管策略、落日志。不直接执行命令。
- **CLI（前台执行器）**：唯一有执行权的地方。所有命令都是 CLI 的子进程，跑在 PTY 里，所以 Ctrl+C、作业控制、sudo 密码提示全部跟原生终端一致。
- **daemon 不跑命令**这条是硬约束：CLI 一死，daemon 立刻把会话标记为 detached 并清理，不留孤儿进程。

### 4.2 模型交互

- DeepSeek 流式（SSE），先出字先显示，不等整段
- 模型不输出自由文本命令，输出结构化动作：
  ```json
  {"action":"explain|suggest|run|inspect","cmd":"...","why":"...","risk":"read|write|destructive|privileged","reversible":true}
  ```
- 策略引擎先校验，再过权限闸门，最后才可能落到执行器

## 5. 协助等级

| 级 | 名字 | 行为 | 能执行吗 |
|---|---|---|---|
| L1 | 旁观 | 只记录，不主动说话，你问才答 | 否 |
| L2 | 讲解 | 讲现象和原理，不给命令 | 否 |
| L3 | 指路 | 给方向、关键词、man 页位置 | 否 |
| L4 | 代笔 | 给完整命令，你自己敲 | 否（它不执行） |
| L5 | 陪练 | 你点头它执行，默认一步一确认 | 是 |

- 默认 **L3**
- 切级：`dojo level 4`，只对当前会话生效；写进 config 才是默认
- L5 也分两种模式：
  - `step`（默认）：每步都要 y
  - `batch`：一口气跑完一个计划，实时输出，随时 Ctrl+C（仍然受风险等级限制）

## 6. 停止设计（重点）

> 原则：不让人停在半截。Ctrl+C 不是砍刀，是刹车。

### 6.1 四个入口

| 入口 | 场景 | 行为 |
|---|---|---|
| **Ctrl+C 一次** | dojo 代跑的命令正在跑 | 刹车：不立刻杀进程，弹选项，15 秒无操作走默认 |
| **Ctrl+C 连按两次** | 你已经想好了 | 跳过询问，直接执行默认动作（回滚） |
| **确认点 y/n/q** | L5 step 模式 | n 跳过本步，q 取消剩余步骤 |
| **`dojo stop`** | 不在这个窗口 / 终端卡住 | 等同 Ctrl+C 一次，由 daemon 转发给执行器 |

实现要点：
- dojo 代跑的命令放进**独立进程组**，CLI 自己 trap 掉 SIGINT。所以第一次 Ctrl+C 只到 CLI，不会当场砍断命令，选项定了才给进程组发信号
- 你自己手敲的命令完全不接管，Ctrl+C 就是原生行为
- 生成回答过程中按 Ctrl+C 只取消这次生成，不发命令

### 6.2 按下去之后问什么

```
这条还在跑：mv ~/messy/*.log ~/logs/（已移动 2 个）
[1] 中断并回滚到执行前        默认（15 秒后自动执行）
[2] 让它跑完，然后停手
[3] 中断，保留现场
[4] 不停了，继续
```

- 默认 1，回车或超时都走它
- 这条不可逆（比如 apt）时，1 不可选，默认自动变成 2，并注明「这条没法回滚」
- 选 1 / 2 / 3 都等于终止计划，剩余步骤取消；想反悔就选 4

### 6.3 回滚怎么做

顺序固定，不做「尽力而为」：

1. SIGTERM 到进程组，等 5 秒
2. 没退就 SIGKILL，再等 2 秒
3. `pgrep -g` 确认没有残留子进程
4. 按快照逆序恢复：新建的删掉、覆盖的写回、权限改回
5. 校验：文件存在性、大小、关键文件 hash
6. 出报告：成功就说成功；失败就说清哪一步没还原，给人工命令

回滚失败不重试，直接交给人。

### 6.4 回滚的边界

| 操作 | 可撤销 | 方式 |
|---|---|---|
| 写/覆盖已存在文件 | 是 | 执行前快照，逆序写回 |
| 新建文件/目录 | 是 | 删除新建物 |
| mv / cp（受管目录内） | 是 | 逆操作 + 快照兜底 |
| rm（受管目录内） | 有快照才行 | 没快照就直说「救不回来」 |
| chmod / chown | 是 | 记录原权限位 |
| apt / dnf / pip 安装 | 否 | 只给卸载命令，不自动跑 |
| systemctl start/stop/restart | 否 | 只给反向命令 |
| dd / mkfs / 分区 / 内核参数 | 否 | 事前拦截，必须打字确认 |

规则：
- 快照只做**单文件 ≤ 50MB、单步 ≤ 200MB**，超了就不跑，先问你
- 快照放 `~/.local/state/dojo/snapshots/<session>/<step>/`，默认留 7 天
- `destructive` / `privileged` 的命令，L5 也不许 batch 跑，必须打字确认（输入 `确认` 两个字，不是 y）
- 回滚本身出问题，不回滚「回滚」，只报告

### 6.5 询问还是偏好：两个都要

- 默认 `on_interrupt = "rollback"`：问的时候默认就是回滚，不选就回滚
- 想彻底不弹窗：`stop.ask = false`，按下去直接回滚，连问都不问
- 首次使用会问一次，并提示「以后可以不问」，选了就写进配置
- 单次任务可以临时覆盖：`dojo run --on-stop=finish_step`

```toml
# ~/.config/dojo/config.toml
[assist]
level = 3               # 1..5
mode = "step"           # step | batch（仅 L5 有效）

[stop]
on_interrupt = "rollback"  # rollback | finish_step | keep | ask
ask = true                 # false = 不弹选项，直接按 on_interrupt 执行
ask_timeout_seconds = 15
double_ctrl_c = "rollback"
grace_seconds = 5          # SIGTERM 到 SIGKILL

[undo]
enabled = true
max_file_mb = 50
max_step_mb = 200
ttl_days = 7

[safety]
require_typed_confirm = ["destructive", "privileged"]
deny_paths = ["/etc", "/boot", "/usr", "/var/lib"]
max_steps = 5
max_step_seconds = 600

[model]
provider = "deepseek"
stream = true
```

## 7. 状态机

```
IDLE
 ├─(提问)→ THINKING ─(回答完)→ IDLE
 └─(要执行)→ PLANNING → WAITING_APPROVAL
                          ├─(y)→ RUNNING ─(成功)→ 下一步 / DONE
                          ├─(n)→ PAUSED
                          └─(q)→ ABORTED

RUNNING ─(Ctrl+C / dojo stop)→ ASKING
ASKING ├─(1 / 超时，可逆)→ ROLLING_BACK → PAUSED
       ├─(1 / 超时，不可逆)→ FINISHING → PAUSED
       ├─(2)→ FINISHING → PAUSED
       ├─(3)→ PAUSED（保留现场）
       └─(4)→ RUNNING

PAUSED ├─(继续)→ WAITING_APPROVAL
       ├─(undo)→ ROLLING_BACK → PAUSED
       └─(结束)→ IDLE

ABORTED → 现场报告 → IDLE
```

约束：
- `RUNNING` 同一时刻只允许一个子进程
- `ASKING` 有倒计时，15 秒无输入按默认执行
- `ROLLING_BACK` 期间不接受新命令，只打印进度
- `PAUSED` 超过 30 分钟无操作 → 自动 ABORTED（防僵尸会话）
- CLI 退出 → daemon 立即清理，状态落盘供 `dojo log` 回看

## 8. 数据与日志

- 会话日志：`~/.local/state/dojo/sessions/<id>.jsonl`，每行一个事件（命令、输出摘要、审批、信号、快照）
- 输出只存前 200 行 + 后 50 行，中间截断，避免日志爆炸
- 敏感串过滤：`sk-*`、`token=`、`password=`、`Authorization:` 一律打码后再落盘和喂模型
- 默认保留 30 天，`dojo log` 可回看；`dojo log --replay` 只读重放，不执行

---

## 9. 安全红线

1. 不存任何密码，不代输 sudo 密码；sudo 提示走原始终端
2. 不主动提权；要 root 的命令必须你自己敲 sudo
3. 模型输出永远过策略引擎，白名单外一律拒绝执行
4. `deny_paths` 命中直接拒绝，不给「确认后可以」的口子
5. 一条计划最多 5 步，单步最长 10 分钟，超时自动中断
6. 网络出口只有模型 API，不上传命令日志和文件内容（除非你显式 `dojo share`）
7. 卸载即干净：`dojo uninstall` 删二进制、hook、systemd unit、state 目录

## 11. 分期实现

| 期 | 内容 | 验证标准 |
|---|---|---|
| P0 | 本文件 | 你点头 |
| P1 | shell hook + ask/explain + 流式回答（L1-L4，不执行） | 报错后问一句，能结合 stderr 答对 |
| P2 | L5 单步执行 + 确认点 + Ctrl+C 刹车 + 快照回滚 | 中途按下停，机器能回到执行前，校验通过 |
| P3 | 三种停法可选 + config + `dojo undo` + 现场报告 | 覆盖文件能还原；apt 类明确拒绝并给反向命令 |
| P4 | batch 模式 + `dojo stop` 跨终端 + 日志重放 | 另一个终端能停掉正在跑的任务 |
| P5 | zsh/fish、install.sh、发行版打包 | 一台干净机器上一条命令装完 |

P1 就能用，P2 才敢让它动手。

## 13. v0.5 增补：沙盒预演与 PTY 输出

### 13.1 overlayfs 预演（`dojo preview`）

静态解析猜不到的命令（脚本、Makefile、`git clean`）以前只能整目录快照或放弃回滚。v0.5 加了另一条路：

```
unshare -Urm --propagation private bash -c '
  mount -t overlay overlay \
    -o lowerdir=$PWD,upperdir=<state>/sandbox/<id>/upper,workdir=<state>/sandbox/<id>/work \
    <state>/sandbox/<id>/merged &&
  cd <state>/sandbox/<id>/merged &&
  exec bash --noprofile --norc -c "$CMD"'
```

- 用户命名空间内 mount，不需要 root，不需要事先挂载
- 跑完扫 upper 层：普通文件是新增/修改，字符设备 0:0 是 whiteout，即删除
- 应用时按「删除 → 目录 → 文件」顺序合回原目录；丢弃就直接删沙盒目录
- 边界：只覆盖当前目录一层，绝对路径写到 `~` / `/tmp` / `/etc` 不在隔离范围

### 13.2 PTY 输出捕获

- `dojo run/exec`：子进程 stdout/stderr 接到同一对 PTY，父进程边转发边写 `runs/<id>/output.log`；因此 `isatty(1/2)` 为真、颜色保留，同时有完整日志可回看
- shell hook 的 `capture_stderr`：用 python 开一对 PTY，把 slave 接到 fd 2，后台进程从 master 转发到 `/dev/tty` 并追加日志。`isatty(2)` 不再被破坏，之前「彩色工具变无色」的问题消失
- 刹车菜单弹出时用线程继续泵 PTY，避免子进程因管道写满卡住

## 14. v0.6 增补：ACP 接入与 FIM 补全

### 14.1 为什么是 ACP

dojo 的契约是「你操作，它陪」，所以它不适合当能自己改文件的 agent。ACP 正好把这件事拆开：编辑器当 Client，负责文件系统和终端；dojo 当 Agent，只负责想和说。两边用 JSON-RPC 2.0 在 stdio 上通信。

最小实现：

| 方法 | 方向 | 处理 |
|---|---|---|
| `initialize` | C→A | 回 protocolVersion=1、能力、agentInfo，authMethods 空 |
| `authenticate` | C→A | 直接成功（不需要认证） |
| `session/new` | C→A | 分配 sess_xxx，记 cwd 和空历史 |
| `session/prompt` | C→A | 组 system+历史+本轮文本，流式调模型，边收边发 `session/update`，最后回 stopReason |
| `session/cancel` | C→A | 通知，置位 Event，流式循环里检查后提前停，stopReason=cancelled |

不实现 `session/load`（不持久化历史）、不实现 fs/* 和 terminal/*，能力声明里如实写 false。

并发模型：一个读线程负责 stdin，把 cancel 转成 Event、其余请求丢进队列；主线程串行处理，保证输出顺序。

### 14.2 FIM 补全

DeepSeek 的 FIM 在 `/beta/completions`，参数是 `prompt` + `suffix`。dojo 只暴露一层薄封装：`dojo complete -p ... [-s ...] [-n N]`，输出纯补全文本（无换行），方便 shell 部件接。

不做的部分：不内置 zsh/bash 的补全 widget，不常驻进程。谁想接，自己包一层函数即可，这样 dojo 仍然保持「没有后台常驻」的边界。
