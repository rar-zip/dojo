# dojo 演进路线图（v0.7 → v1.0）

前提：守住 **「你是司机、它是副驾，零第三方依赖、无常驻进程」** 这个契约。不往重型全自动 Agent 方向膨胀。

已落地能力版图：PTY 报错捕获、空敲直答、L5 快照回滚、OverlayFS 沙盒、ACP 编辑器接入、FIM 补全。

---

## 一、v0.7 交互手感闭环

后端已经通了，缺的是「最后一公里」，现在还靠手动复制粘贴或敲长命令。

### 1. 报错卡片一键选号执行

- **痛点**：空敲 `dojo` / `dojo why` 给出「方案 1 / 2 / 3」后，用户得用鼠标复制再粘回终端
- **做法**：`cmd_error_answer` / `cmd_why` 打印完方案后，交互终端下顺手接一句轻量交互；或支持 `dojo 1` / `dojo 2` 指代上一张报错卡片的第 N 条方案
- **执行走 `Runner`**，带跑前快照，随时可 `undo`

### 2. Shell 原生行内补全绑定

- **痛点**：`dojo complete` 支持 `\0` 管道传前后文，但没人会手敲 `dojo complete -p "..."`
- **做法**：
  - `lib/hook.bash`：`bind -x` + `READLINE_LINE` / `READLINE_POINT`
  - `lib/hook.zsh`：`zle -N` + `LBUFFER` / `RBUFFER`
  - 约 15 行，默认 `Alt+.` 或 `Ctrl+G`，按下就把补全结果塞到光标处

### 3. `dojo diff` 回滚前预览

- **痛点**：`dojo undo` 前只知道碰了哪些路径，看不到改了哪几行
- **做法**：新增 `dojo diff [运行ID]`，拿 `runs/<id>/steps/` 的备份与当前工作区做 `diff -u`

## 二、v0.8 快照与沙盒双网合一

`dojo exec`（静态解析快照）和 `dojo preview`（OverlayFS 沙盒）现在是平行两条路，用户得自己判断何时用 preview。

### 1. 猜不准时自动提议进沙盒

- 位置：`Runner._execute`（`bin/dojo:1761` 附近）
- 条件：`analyze(cmd)` 发现 `xargs`、命令替换 `$()`、`eval`，即 `snap.unsupported` 非空，或需要整目录快照 `snap.coarse=True`
- 且 `sandbox_available()` 为真
- 行为：不再只打印「跑坏了撤不回来，你自己掂量」，改成问一句「这条命令静态猜不准影响面，要先放进沙盒预演看改动清单吗？(Y/n)」

### 2. 沙盒改动应用前自动转存为可 undo 快照

- 现状：`cmd_preview` 选「应用改动」（`_apply_upper`）合并回真实目录后，这次改动不进 `runs/`，没法 `dojo undo`
- 做法：覆盖真实目录前，把 `_preview_diff` 列出的受影响真实文件存成标准 `Run` 快照
- 结果：沙盒应用后的改动也能 `dojo undo`，两套机制并成一套闭环

## 三、v0.9 视野精准扩展（不破只读隐私契约）

### 1. ACP 编辑器模式共享终端报错现场

- 现状：`acp_messages`（`bin/dojo:2222` 附近）写死「你看不到终端历史，只能看到编辑器发来的内容」
- 但 dojo 的独门优势就是 `~/.local/state/dojo/ctx.tsv` 和 `stderr.log`
- 做法：同工作目录（或最近 5 分钟内）的终端命令记录 + `last_stderr` 附进 system prompt
- 效果：在 Zed 里直接问「刚才终端为什么报错」，能结合正在编辑的代码一起答

### 2. 报错行局部代码自动摘取（受控探针）

- 触发：空敲 `dojo` 分析报错时，`last_stderr` 里出现当前目录下的文件名与行号（如 `./deploy.sh: line 24`、`File "main.py", line 18`）
- 行为：自动读取该行上下各 5 行
- 约束：过 `redact_sensitive` 脱敏，严格排除 `deny_paths` 和隐藏文件
- 效果：`solutions` 精确到行，不再是泛泛的排查命令

## 四、v1.0 工程结构升级

现状：`bin/dojo` 单文件 3300+ 行 / 120 KB+，继续塞功能会让阅读、定位、合并冲突越来越痛。

- **开发态拆分**：实现拆到 `src/dojo/`，如 `config.py`、`parser.py`、`snapshot.py`、`runner.py`、`sandbox.py`、`acp.py`、`cli.py`，每个模块 300–500 行，单测按模块独立挂载
- **分发态仍单文件**：升级 `tools/build_installer.py`，构建时按依赖顺序拼接（或 `zipapp`）生成 `bin/dojo`，再打进 `dist/dojo-install.sh`
- 对外仍是「一个脚本、零第三方依赖、`wget | bash` 即装即用」
